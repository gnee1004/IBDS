# IBDS 실행 방법

모든 명령은 프로젝트 루트에서 실행합니다. ZAP과 테스트 서버를 준비한 뒤, 웹 화면에서 설정 → 스캔 실행 → 리포트 확인 순서로 사용합니다.

## 0. 사전 설치

1. Docker Desktop을 설치하고 실행합니다.
2. Python 가상환경을 생성하고 활성화합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

3. 의존성과 판정에 사용하는 Playwright Firefox를 설치합니다. 아래 설치는 최초 환경 준비 시 진행합니다.

```powershell
python -m pip install -r requirements.txt
python -m playwright install firefox
```

직접 탐색할 때 사용하는 Firefox와 Playwright의 판정용 Firefox는 별도로 준비합니다.

## 1. ZAP 준비

### 최초 설정

```powershell
.\zap_setup.ps1
```

스크립트가 다음을 처리합니다.

- ZAP Docker 이미지 다운로드와 컨테이너 시작. 기본 포트는 `8081`입니다.
- ZAP 초기화 완료 대기.
- 프로젝트 루트에 `zap_root_ca.cer` 인증서 저장.
- `config/zap_config.json` 자동 생성.

`config/zap_config.json`은 직접 편집하거나 웹 화면에서 설정하는 파일이 아닙니다. ZAP 연결 정보는 기존 설정 스크립트에서 관리합니다. 스크립트를 다시 실행하면 기존 `zap` 컨테이너를 제거하고 재생성하므로, 평소 재시작에는 아래 명령을 사용합니다.

### 이후 실행

```powershell
docker start zap
```

## 2. 탐색용 Firefox 설정

### PC의 IP 확인

```powershell
ipconfig
```

사용 중인 이더넷 또는 Wi-Fi 어댑터의 IPv4 주소를 확인합니다.

### 프록시 설정 — 최초 1회

Firefox의 `about:preferences#general` → 네트워크 설정 → 수동 프록시 설정으로 이동합니다.

- HTTP 프록시: ZAP을 실행한 PC의 IPv4 주소.
- 포트: `8081`.
- HTTPS에도 같은 프록시를 적용합니다.

### 인증서 설치 — 최초 1회

Firefox 설정의 인증서 관리에서 프로젝트 루트의 `zap_root_ca.cer`를 가져오고, 웹사이트 식별용 인증기관 신뢰 항목을 선택합니다.

## 3. 테스트 대상 서버 준비

이미 사용하는 대상 서버가 있으면 해당 서버를 실행하고 실제 접속 주소를 사용합니다.

DVWA를 새로 구성하는 경우의 예시입니다. 아래 예시는 외부 포트를 `8090`으로 지정합니다.

```powershell
docker run -d --name dvwa -p 8090:80 vulnerables/web-dvwa
```

기존 `dvwa` 컨테이너가 있으면 새로 만들지 않고 시작합니다.

```powershell
docker start dvwa
```

기존 컨테이너를 시작한다고 포트가 바뀌지는 않습니다. 이전에 `8080:80`으로 생성했다면 접속 주소도 `:8080`을 사용합니다. 포트는 `docker ps`의 PORTS 항목에서 확인할 수 있습니다.

Firefox에서 `http://본인IP:8090`으로 접속합니다. 처음 구성한 DVWA는 Setup 페이지에서 DB를 초기화한 뒤 `admin` / `password`로 로그인합니다.

예를 들어 서버 IP가 `192.168.55.201`이고 포트가 `8090`이면 주소는 `http://192.168.55.201:8090`입니다. IP와 포트는 자신의 환경에 맞게 사용합니다.

## 4. 로그인 및 탐색 기록 준비

1. 프록시를 설정한 Firefox에서 테스트 대상 주소에 접속합니다.
2. 로그인한 뒤 검사할 페이지를 이동하고 검색·폼 입력 등을 수행합니다.
3. ZAP에 쌓인 요청과 로그인 세션을 이후 웹 스캔에서 사용합니다.

테스트 대상은 `localhost` 대신 실제 서버 IP로 접속합니다. 로컬 주소는 브라우저의 프록시 우회 설정에 영향을 받을 수 있습니다.

## 5. IBDS 웹 UI 실행

가상환경이 활성화된 터미널에서 다음 명령 하나를 실행합니다.

```powershell
python src/web/app.py
```

브라우저에서 **http://127.0.0.1:1080** 에 접속합니다. 이 주소는 IBDS 조작 화면이며, 검사할 대상 서버 주소와 다릅니다.

실행 옵션은 필요하지 않습니다. 타겟 주소와 재방문 주소는 웹 화면에서 입력합니다. 별도의 수집 스크립트를 실행할 필요도 없습니다. 스캔 시작 버튼이 수집부터 판정까지 연결합니다.

### 스캔 설정

1. **타겟 URL**에 테스트 대상 주소를 입력합니다.
2. **설정 저장**을 누릅니다.
3. 필요한 경우에만 **재방문 주소**를 추가합니다.

재방문 주소는 저장형 XSS의 자동 추정 주소가 틀렸을 때 사용하는 보조 설정입니다. 원본 주소 A와 결과를 다시 확인할 주소 B를 매핑합니다. 필요하지 않으면 비워둡니다.

### 스캔 실행

1. **스캔 실행** 화면에서 대상 주소를 확인합니다.
2. **스캔 시작**을 누릅니다.
3. 진행률, 요청 실패 건수, 실행 로그를 확인합니다.

- 수집 중에는 전체 검사 항목 수가 아직 없으므로 퍼센트 대신 수집 중 상태가 표시됩니다.
- 수집 후에는 검사할 파라미터 단위인 ScanPoint의 완료 수를 기준으로 진행률을 표시합니다. 항목별 요청 수가 달라 진행 속도가 일정하지 않을 수 있습니다.
- 개별 요청·판정 실패는 로그에 강조 표시됩니다. 전체 파이프라인이 멈추는 오류는 화면 상단에 원인이 표시됩니다.
- 한 번에 스캔 하나만 실행할 수 있습니다.

**설정 변경을 눌러도 진행 중인 스캔은 멈추지 않습니다.** 설정 화면으로 이동할 뿐이며, 실행 중에는 설정 저장이 차단됩니다. 설정을 바꾸어 다시 검사하려면 중지 후 중단 완료를 기다리고, 설정을 저장한 다음 새 스캔을 시작합니다.

### 스캔 중지

**중지** 버튼은 현재 요청과 재조회 처리를 마친 뒤 안전하게 멈추도록 요청합니다. 바로 강제 종료되는 방식은 아닙니다.

- 수집 중에 누르면 수집이 끝난 뒤 공격 단계에 들어가기 전에 중단됩니다.
- 요청 처리 중에 누르면 이미 수행한 요청의 판정과 결과 저장을 마무리하므로 잠시 기다릴 수 있습니다.
- 중단 완료 시 **사용자에 의해 중단됨**으로 표시됩니다.
- 그때까지 기록된 결과는 보존되며 리포트에서 다시 볼 수 있습니다.

## 6. 리포트 확인

완료 또는 중단 후 **리포트 보기**를 누릅니다. 상단 **실행 기록**에서 과거 실행도 선택할 수 있습니다.

- 상단 요약에서 취약·반사됨·판단보류·안전과 에러 건수를 확인합니다.
- **에러 · 상세 보기**를 누르면 실패한 대상·파라미터·단계·원인을 확인할 수 있습니다. 에러 요약 박스 또는 펼쳐진 상세 박스를 더블클릭하면 접힙니다. 닫기 버튼도 사용할 수 있습니다.
- 결과 행을 펼치면 같은 URL·파라미터에서 나온 payload와 공격기법별 판정 근거가 표시됩니다.
- **판정기준**과 **공격기법** 필터를 동시에 적용할 수 있습니다. 선택지는 해당 실행 결과에 따라 달라집니다.
- **정렬**에서 심각도 순 또는 URL / 파라미터 이름순을 선택합니다.
- **새로고침**은 실행 기록과 결과를 다시 읽으며, 스캔을 새로 시작하지 않습니다.
- 결과가 없거나 필터에 맞는 항목이 없으면 안내 문구가 표시됩니다.

## 7. 저장 파일

- `config/target_config.json`: 웹에서 저장한 타겟 URL과 재방문 주소 매핑.
- `config/zap_config.json`: ZAP 준비 스크립트가 자동 생성하는 연결 정보.
- `results/collection_날짜_시간_마이크로초/`: 웹에서 시작한 실행별 결과 폴더.
  - `zap_messages.json`: 수집한 원본 요청·응답.
  - `scan_targets.json`: 검사할 대상으로 정리한 요청 목록.
  - `request_results.jsonl`: 수행한 요청·응답 결과.
  - `findings.jsonl`: 판정 및 오류 기록.
  - `run_meta.json`: 실행 상태, 진행 수, 실패 수, 시작·종료 시각.

중단 또는 실패 시에는 해당 단계까지 생성한 파일만 있을 수 있습니다. 예전 형식의 실행 폴더도 조회할 수 있지만, 종료 상태 기록이 없으면 상태 정보 없음으로 표시됩니다.

## 8. 종료 및 다음 실행

스캔 중이라면 웹 화면에서 중지하고 중단 완료를 기다립니다. 이후 웹 서버 터미널에서 `Ctrl+C`로 서버를 종료합니다.

ZAP과 DVWA도 종료하려면 다음 명령을 사용합니다.

```powershell
docker stop zap
docker stop dvwa
```

다음 실행 시에는 Docker Desktop을 실행하고 컨테이너를 시작한 뒤, 가상환경 활성화와 웹 서버 실행을 진행합니다.

```powershell
docker start zap
docker start dvwa
.\.venv\Scripts\Activate.ps1
python src/web/app.py
```

대상 로그인이 만료되었다면 프록시를 설정한 Firefox에서 다시 로그인하고 필요한 페이지를 탐색합니다.

## 9. 실행이 잘 안 될 때

### 수집 결과에 로그인 페이지만 나타나는 경우

- Firefox 프록시 주소와 포트가 맞는지 확인합니다.
- 대상 서버에 로그인되어 있고 실제 검사 페이지에 접근 가능한지 확인합니다.
- 로그인 세션이 만료되었으면 다시 로그인하고 검사 페이지를 탐색한 뒤 새 스캔을 실행합니다.
- 필요한 경우 Firefox를 완전히 종료했다가 다시 실행하거나 새 개인정보 보호 창에서 로그인합니다.

### 상단에 연결 또는 수집 실패가 표시되는 경우

- `docker ps`로 ZAP과 대상 컨테이너의 실행 상태 및 포트를 확인합니다.
- 웹 설정의 타겟 URL이 실제 접속 주소와 같은지 확인합니다.
- `docker logs zap`으로 ZAP 시작 오류를 확인합니다.

### 화면 수정이 바로 보이지 않는 경우

- 페이지를 새로고침합니다. 이전 화면이 계속 보이면 `Ctrl+F5`로 새로 불러옵니다.
